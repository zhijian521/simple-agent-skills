# 代码与文档同步

## 影响矩阵

| 变化 | 必须检查 | 条件性检查 |
| --- | --- | --- |
| 新增、删除或改变用户功能 | 需求、功能、对应功能模块文档 | README、帮助文档、方案状态 |
| 修改入口、权限、快捷键、默认值、交互或错误反馈 | 功能文档 | 影响验收边界时更新需求文档 |
| 修改目录、模块职责、依赖方向或关键数据流 | 架构文档、对应开发规范 | AGENTS 速查、审查清单 |
| 新增、删除或修改 API | 接口文档、相关类型或契约 | 功能文档、Route 注释、OpenAPI |
| 修改数据模型、数据库、持久化或迁移 | 架构或专项技术文档 | 需求、功能、部署、初始化脚本 |
| 修改构建、部署、环境变量或运行命令 | README、部署文档 | 架构文档、AGENTS、示例环境文件 |
| 修改测试工具、质量门禁或开发约束 | 对应开发规范、规范导航 | README、CI 文档 |
| 实施设计方案 | 方案状态、产品和技术当前基线 | 删除或归档已失效方案 |

## 同步流程

1. 读取当前 diff 和相关实现，列出真实行为变化。
2. 使用影响矩阵确定候选文档，不先全仓机械改日期。
3. 核对候选文档是否已经准确；准确则无需改动。
4. 更新内容、关联代码和导航；仅在整篇复核后更新核对日期。
5. 运行项目已有文档检查和统一质量门禁。

## 无需机械更新的场景

- 不改变用户行为、架构边界或公共契约的内部重构。
- 不影响语义的格式化、命名整理和局部样式调整。
- 已有文档使用抽象描述且仍然准确的实现替换。

即使无需修改，也要确认现有描述没有被破坏；交付时可简短说明“已核对，无文档变化”。

## 漂移处理

- 代码与当前基线冲突：以代码和可执行事实为准，修正文档。
- 代码偏离设计方案：记录实际决策，更新方案，不假装按原方案落地。
- 多份文档重复且冲突：确定唯一职责文档，其他位置改为链接或删除。
- 无法从代码确认业务语义：标记假设并请求项目负责人确认，不自行补写事实。
