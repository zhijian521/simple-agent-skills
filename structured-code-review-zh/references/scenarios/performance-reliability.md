# 性能与可靠性规则

## 数据访问

- 循环内查询、N+1、逐条写入和重复获取，只有迭代规模可增长且由此造成额外 I/O 或明确成本时报告；
  固定小集合、初始化和逐项语义必需的路径不报告。
- 大结果只有输入或生产规模无界、且实现会整体物化或影响可用性时要求分页、流式或限制大小；
  采用分页时检查排序稳定性和重复/遗漏。
- 事务中包含远程调用或长计算时，只有锁持有、超时或重试会破坏原子性、吞吐或幂等性时报告。
- 连接、游标、response body 和流由当前代码拥有且在可达路径上未释放时报告。

## 算法与内存

- 只有数据规模和热路径可信时才报告复杂度；说明输入增长时的实际影响。
- 检查嵌套扫描、重复排序/解析/序列化、无界队列/缓存/集合和大对象复制。
- 流式数据被整体物化、缓存缺少大小/TTL/隔离/失效策略时，只有数据规模、生命周期或跨用户影响可证明时报告。

## 网络、重试与超时

- 外部调用缺少超时或取消传播时，只有请求、worker 或批处理可能无限等待、占满资源或错过关闭信号时报告。
- 重试只有覆盖非瞬时错误、没有上限/退避/幂等保护，或会与上层重试相乘形成可达请求风暴时报告。
- 非幂等操作被重试且无幂等键、去重或其他等价保护时报告。
- 批量并发只有并发量可由外部输入放大、资源被耗尽或错误语义导致调用方误判时报告。

## 并发与生命周期

- 证明共享状态并发可达后再报告竞态、死锁和可见性问题。
- 锁不能跨远程 I/O、用户回调和未知耗时操作；检查锁顺序和异常释放。
- worker、goroutine、task、线程和订阅只有缺少退出、取消、回收或错误观察而可能泄漏、丢失失败或阻止关闭时报告。
- 定时任务和消息消费只有协议或当前实现允许重复投递、乱序、毒消息、积压或关闭竞争时检查相应处理。

## 可观测性

- 关键失败不能静默；日志需包含定位所需上下文，但不得包含秘密。
- 指标标签不能使用用户 ID、URL 全量等高基数字段。
- trace/context/correlation id 应跨异步和网络边界传播。

## 不应报告

- 没有数据规模、频率或热路径证据的微优化。
- 一次性启动代码、测试辅助或小型固定集合中的普通线性操作。
