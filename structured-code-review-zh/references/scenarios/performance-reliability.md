# 性能与可靠性规则

## 数据访问

- 检查循环内查询、N+1、逐条写入、缺少批量操作和重复获取相同数据。
- 大结果必须分页、流式或限制大小；分页需要稳定排序并避免重复/遗漏。
- 事务范围不能包含不必要的远程调用或长计算；失败必须回滚且保持幂等。
- 连接、游标、response body 和流必须在所有路径释放。

## 算法与内存

- 只有数据规模和热路径可信时才报告复杂度；说明输入增长时的实际影响。
- 检查嵌套扫描、重复排序/解析/序列化、无界队列/缓存/集合和大对象复制。
- 流式数据不能被无意整体物化；缓存必须有大小、TTL、隔离和失效策略。

## 网络、重试与超时

- 外部调用必须有合理连接/读取/整体超时和取消传播。
- 重试只针对瞬时错误，并有上限、退避、抖动、幂等保护和 Retry-After 处理。
- 禁止重试不可幂等操作而没有幂等键；禁止多层重试相乘造成请求风暴。
- 批量并发必须有限制，错误语义要区分全失败、部分失败和取消。

## 并发与生命周期

- 证明共享状态并发可达后再报告竞态、死锁和可见性问题。
- 锁不能跨远程 I/O、用户回调和未知耗时操作；检查锁顺序和异常释放。
- worker、goroutine、task、线程和订阅必须有退出、取消、回收和错误观察机制。
- 定时任务和消息消费要处理重复投递、乱序、毒消息、积压和优雅关闭。

## 可观测性

- 关键失败不能静默；日志需包含定位所需上下文，但不得包含秘密。
- 指标标签不能使用用户 ID、URL 全量等高基数字段。
- trace/context/correlation id 应跨异步和网络边界传播。

## 不应报告

- 没有数据规模、频率或热路径证据的微优化。
- 一次性启动代码、测试辅助或小型固定集合中的普通线性操作。
