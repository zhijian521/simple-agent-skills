# 现代变更风险规则

只读取与当前变更相关的章节。本文件补充通用工程风险，不替代仓库自身政策。

## 公开契约与发布

- API、事件、数据库和配置变更要检查旧生产者/消费者、缓存数据和滚动发布期间的新旧版本共存。
- 破坏性迁移采用 expand/migrate/contract：先扩展兼容结构，再回填和切流，最后删除旧结构。
- 高风险发布检查回滚或前滚路径、feature flag/kill switch、健康检查、容量、超时和降级行为。
- 只有变更会影响已有 SLO、告警或故障恢复时才要求可观测性；不要泛化要求每段代码新增日志指标。

## 依赖与供应链

- 新依赖要验证来源、锁文件、版本范围、运行时用途、维护状态和许可证是否符合仓库政策。
- Git/VCS、容器、Action、模块和下载产物应固定不可变 revision 或摘要；可信官方工具的稳定主版本标签可按仓库政策接受。
- 安装/构建钩子、插件和生成器会执行代码；检查其权限、来源和是否在生产安装路径意外运行。
- 不凭记忆报告 CVE。只有锁定版本和可靠 advisory 能证明受影响时才报告漏洞。
- SBOM、签名、provenance 和依赖审计属于发布/合规能力；仅在仓库已有政策或变更削弱现有能力时作为问题。
- SBOM 变更检查组件版本、哈希、许可证和依赖关系是否与锁文件/构建产物一致；生成器造成的排序或
  时间戳变化不报告。不要因为仓库没有 SBOM 就默认阻止普通业务变更。

## 隐私与用户数据

- 新增采集、日志、分析、导出或共享时检查数据最小化、用途、保留期限、删除路径和访问边界。
- Token、提示词、附件、遥测、错误报告和追踪字段都可能包含个人或机密数据；检查脱敏和租户隔离。
- 不根据字段名称臆测法规问题；必须证明数据类别、流向和可观察后果。

## 用户界面与可访问性

- 交互控件检查语义、键盘操作、焦点管理、可访问名称和状态反馈；动态更新不能只靠颜色表达。
- 表单错误应与字段关联；模态框和菜单应正确管理焦点，异步加载/失败状态应可感知。
- 只有变更引入真实交互障碍时报告，不把通用 WCAG 清单机械套到无关 diff。

## AI 与 LLM 功能

- 把用户输入、网页、检索文档、工具输出和模型输出都视为不可信数据；提示文本不能授予权限。
- 工具调用、文件/网络访问和外部副作用必须由确定性代码做权限校验、参数约束和用户确认，不能只依赖模型服从提示。
- 模型生成的 SQL、命令、HTML、URL、代码和结构化数据必须经过 schema、allowlist、编码或沙箱验证后才能执行。
- 检查 prompt injection、跨租户检索、秘密进入上下文/日志、过宽工具权限和模型输出直达高权限操作。
- 对循环代理和批处理设置步数、token、成本、并发、超时、取消和重试上限；失败不得静默降级为可信答案。
- 模型非确定性本身不是缺陷。只有业务需要可复现、可审计或事实准确时，才检查版本固定、证据引用和评测覆盖。
