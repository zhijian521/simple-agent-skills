# TypeScript、JavaScript 与 React 规则

## 类型与语言语义

- 禁止新增 `var`；使用 `const`，确需重新赋值时使用 `let`。
- 避免 `==`、`!=` 带来的隐式转换；除非项目有明确、经过验证的例外。
- `any` 会绕过类型保护；只有边界适配且有验证或明确原因时允许。
- 解构、属性访问和可选返回值必须处理 `null`/`undefined` 的真实可达路径。
- 检查可选链是否把必要失败静默转换为 `undefined`，以及空值合并默认值是否改变语义。
- 禁止难以推理的嵌套三元表达式；只有它确实导致逻辑歧义或错误风险时报告。
- 检查闭包捕获、循环变量、对象浅拷贝、可变共享引用和原型污染风险。

## 异步处理

- Promise 必须被 `await`、返回或显式处理；检查浮空 Promise 和未处理拒绝。
- 异步错误必须保留原始原因并在正确边界转换，不能无声吞掉。
- 独立任务可用 `Promise.all`；存在顺序或共享状态依赖时必须串行。
- 检查 `Promise.all` 的失败语义、部分成功处理以及是否需要 `allSettled`。
- 定时器、订阅、事件监听、AbortController 和请求必须在生命周期结束时清理。

## React

- Hooks 只能在组件或自定义 Hook 顶层调用，不能位于条件、循环或普通函数中。
- `useEffect` 依赖必须反映读取的响应式值；同时检查清理函数、竞态和过期响应。
- 渲染阶段禁止 API 调用、DOM 修改、状态写入和其他副作用。
- 不在组件函数内声明会导致每次渲染创建新组件类型的嵌套组件。
- 检查列表 key 的稳定性，不能在可重排列表中使用索引造成状态错位。
- `useMemo`、`useCallback`、`React.memo` 只在有成本或引用稳定需求时使用；不把缺少
  这些优化本身当作缺陷。
- 检查受控/非受控输入切换、状态派生重复、卸载后更新和并发渲染下的陈旧闭包。

## 前端安全

- 用户输入不得直接进入 `innerHTML`、`dangerouslySetInnerHTML` 或模板 HTML。
- 禁止对外部输入使用 `eval`、`Function`、字符串形式的定时器和 `document.write`。
- URL 跳转、资源地址和 `postMessage` 必须校验协议、来源和目标。
- 浏览器端代码不得包含服务端秘密；公开配置和秘密配置必须分离。
- 不修改 `Array.prototype`、`Object.prototype` 等原生原型。

## 不应报告

- 只由 ESLint/Prettier 能确定且没有行为后果的格式问题。
- 没有性能证据时缺少 memo 化。
- 类型已严格排除且上游契约可信的空值路径。
