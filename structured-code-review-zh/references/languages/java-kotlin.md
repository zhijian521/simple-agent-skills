# Java 与 Kotlin 规则

## 逻辑与空值

- 检查错误的 if/switch/when 条件、布尔优先级、fall-through、提前退出和无限循环。
- 根据数据来源和调用链确认 NPE 风险；不要仅因类型可空就报告。
- 检查集合首尾、索引、空 Optional、空字符串、分页边界和数值溢出。
- Kotlin 检查 `!!`、平台类型、可空链和 Elvis 默认值是否掩盖必要失败。

## 异常与资源

- 捕获异常后静默成功时报告；宽泛 `Exception` 只有吞掉取消、掩盖不应恢复的错误或扩张恢复范围时报告。
- 原始 cause 丢失或错误消息泄露秘密、SQL、文件系统等细节，只有会阻碍恢复或暴露给非可信边界时报告。
- 文件、流、连接、Statement、ResultSet 和锁由当前代码取得且在异常路径可能存活时，检查可靠关闭；
  容器托管、请求级自动回收或明确所有者负责释放的资源不报告。
- 事务必须覆盖真正的原子边界；检查嵌套事务、异常吞掉和异步越过事务范围。

## 数据库与性能

- 循环内逐条数据库查询或写入只有迭代规模可增长、查询数随之增长且没有批处理或缓存时报告 N+1；
  小型固定集合、初始化脚本和需要逐项事务语义的路径不报告。
- 大数据处理只有输入无上限或生产规模可证时才要求分页、流式或分批；采用分页时检查排序稳定性和游标边界。
- 检查无界缓存、正则灾难回溯、重复序列化和不必要的大对象复制。

## 并发

- 只有能证明多线程调用时才报告竞态。
- 检查 check-then-act、非原子复合操作、不安全延迟初始化和并发集合误用。
- 方法局部变量、不可变对象和只读访问通常无需同步。
- 已由 `synchronized`、Lock、原子类或单线程所有权正确保护时不要报告。
- Kotlin 协程检查取消传播、结构化并发、阻塞调用占用调度器和异常丢失。
- 避免 `GlobalScope` 让任务逃逸所有者生命周期；`async` 结果必须 await 或由明确所有者观察。

## API 与对象契约

- 修改 `equals` 时同步检查 `hashCode`；比较器必须满足传递性和一致性。
- 检查序列化字段、枚举、默认构造、Builder、DTO 和数据库映射的兼容性。
- 公开集合不要意外暴露可变内部状态。
- Kotlin/Java 互操作只在实际存在 Java 调用方时检查平台类型、默认参数暴露、静态入口和空值标注；
  不机械要求 `@JvmStatic`、`@JvmOverloads`。
- 不把表达式函数、`when`、data/sealed class、scope function 或 `val` 等惯用写法偏好作为缺陷，
  除非当前写法已经造成契约或行为错误。
