# 通用代码审查规则

## 正确性

- 检查条件表达式、运算符优先级、短路行为、循环终止、状态转换和提前返回。
- 检查空集合、空字符串、零值、最大最小值、首尾元素、越界和 off-by-one。
- 检查错误是否被忽略、覆盖、误转为成功，或在错误路径返回了不可信默认值。
- 检查资源、事务、锁和临时状态是否在成功、失败、超时、取消路径都正确释放。
- 检查删除、重命名、默认值变化和接口签名变化对现有调用方的影响。

## 安全与权限

- 外部输入进入查询、模板、路径、URL、命令、日志或反序列化之前必须验证或编码。
- 鉴权必须覆盖资源归属、角色、租户、对象级权限和禁用状态，不能只验证已登录。
- 禁止硬编码或输出密码、Token、API Key、私钥、Cookie 和个人敏感信息。
- 安全比较、随机数、签名、加密和证书校验不得被普通字符串比较或弱算法替代。

## 可靠性与性能

- 检查重试是否有上限、退避、超时、取消和幂等保护。
- 检查循环内网络/数据库/I/O、N+1 查询、无界集合、无分页和无界并发。
- 检查并发访问是否有真实共享状态；只有能证明并发可达时才报告竞态。
- 检查缓存键、失效、隔离和一致性，避免跨用户、租户或权限域复用。

## 可维护性

- 命名错误只有会误导调用、破坏契约或影响日志/提示理解时才报告。
- 重复代码只有已产生行为漂移或使安全修复无法一致应用时才报告。
- 注释应解释不直观的约束和原因；不要要求给显而易见的代码添加注释。
- 不把格式化、可由编译器或成熟静态工具确定的普通提示重复作为高优先级问题。

## 误报排除

- 不根据函数名猜测攻击者可控、并发调用、数据规模或资源所有权；搜索调用链确认。
- 不报告上游校验、类型系统或框架契约已经排除的输入。
- 不把理论风险写成确定缺陷；缺少可达路径、触发条件或实际后果时保持沉默。
- 不报告未被本次变更新增或扩大、且与变更无直接关系的旧问题。
