# TypeScript、JavaScript 与 React 规则

## 类型与语言语义

- `var`、`==`、`!=` 和 `any` 是静态工具优先处理的风险信号；只有本次引入的写法已导致作用域、
  隐式转换或未验证边界数据进入错误路径时报告，不将其本身作为 Finding。
- 解构、属性访问和可选返回值只在 `null`/`undefined` 能由数据来源和调用链到达、且缺少保护时报告。
- 检查可选链是否把必要失败静默转换为 `undefined`，以及空值合并默认值是否改变语义。
- 禁止难以推理的嵌套三元表达式；只有它确实导致逻辑歧义或错误风险时报告。
- 检查闭包捕获、循环变量、对象浅拷贝、可变共享引用和原型污染风险。

## 异步处理

- Promise 未被 `await`、返回或显式处理时，确认其拒绝会未观察、调用方会过早继续或任务会被取消后再报告。
- 异步错误未保留原因或被转换为成功时，确认调用方因此无法区分或恢复失败后再报告。
- 独立任务可用 `Promise.all`；只有顺序或共享状态依赖被代码证明时才要求串行。
- 检查 `Promise.all` 的失败语义、部分成功处理以及是否需要 `allSettled`。
- 定时器、订阅、事件监听、AbortController 和请求由组件或长生命周期对象拥有且会跨生命周期存活时，
  检查清理是否遗漏；一次性请求或框架自动清理的资源不报告。

## React

- Hooks 位于条件、循环或普通函数中时，只在调用顺序可能变化或项目未由 lint 阻止时报告。
- `useEffect` 缺失依赖、清理或竞态保护时，说明具体陈旧状态、重复订阅或过期响应路径。
- 渲染阶段的 API 调用、DOM 修改、状态写入等副作用，只有会在重渲染或并发渲染中重复执行并改变行为时报告。
- 组件函数内的嵌套组件、索引 key 和派生状态只有造成组件类型重置、可重排列表状态错位或状态分叉时报告。
- `useMemo`、`useCallback`、`React.memo` 只在有成本或引用稳定需求时使用；不把缺少
  这些优化本身当作缺陷。
- 检查受控/非受控输入切换、状态派生重复、卸载后更新和并发渲染下的陈旧闭包。

## 前端安全

- 用户可控输入直接进入 `innerHTML`、`dangerouslySetInnerHTML` 或模板 HTML，且无可信清洗或上下文编码时报告。
- 外部输入进入 `eval`、`Function`、字符串形式定时器或 `document.write` 时报告；常量受控代码不作为同类漏洞。
- URL 跳转、资源地址和 `postMessage` 只有可由不可信来源控制且缺少协议、来源或目标限制时报告。
- 浏览器端代码包含可用的服务端秘密时报告；公开构建配置或示例占位符不报告。
- 修改原生原型只有污染跨模块行为、破坏枚举或影响不受控对象时报告。

## 不应报告

- 只由 ESLint/Prettier 能确定且没有行为后果的格式问题。
- 没有性能证据时缺少 memo 化。
- 类型已严格排除且上游契约可信的空值路径。
