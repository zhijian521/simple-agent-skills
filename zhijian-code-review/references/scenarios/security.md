# 安全审查规则

## 输入与注入

- 确认攻击者能否控制输入，再检查 SQL/NoSQL、Shell、模板、表达式、LDAP、Header 和日志注入。
- 查询使用参数绑定；动态表名、列名和排序字段必须白名单，不能仅依赖参数占位符。
- HTML 按输出上下文编码；URL、属性、脚本和 CSS 上下文需要不同防护。
- 命令执行使用参数数组和允许列表，避免拼接 Shell 字符串。

## 身份与授权

- 认证只证明身份；每个敏感操作仍需资源级、租户级和角色级授权。
- 检查禁用、冻结、删除、过期和撤销状态是否在所有入口生效。
- 服务端不能信任客户端传入的 userId、role、price、tenant 或权限字段。
- 检查 IDOR、权限缓存失效、批量接口遗漏校验和后台任务越权。

## 秘密与密码学

- 禁止提交、记录、返回或前端打包秘密和敏感个人数据。
- 密码使用专用慢哈希；Token/签名比较使用常量时间方式并正确处理长度。
- 使用安全随机源、足够熵、可信算法和证书校验；禁止自制加密协议。
- 错误消息、遥测、URL、指标标签和缓存键不能泄露秘密。

## 文件、URL 与反序列化

- 文件路径规范化后验证仍位于允许根目录，防止 `..`、符号链接和编码绕过。
- 上传检查大小、类型、扩展名、存储位置、执行权限和文件名；不要仅信任 MIME。
- 服务端请求 URL 需要协议/主机/IP 白名单，阻止内网、元数据和重定向绕过 SSRF。
- 禁止对不可信数据使用可执行对象反序列化；限制类型、深度和负载大小。

## Web 与会话

- Cookie 设置 Secure、HttpOnly、合适 SameSite；状态变更请求需要 CSRF 防护。
- CORS 不得把凭据与宽泛 origin 组合；检查 origin 精确匹配和预检语义。
- 重定向、OAuth callback、postMessage 和 iframe origin 必须校验。

## 严重级别

- 可远程利用的认证绕过、任意代码执行、秘密泄露、跨租户访问通常为 P0/P1。
- 需要特定权限、配置或难以到达但真实的安全缺陷通常为 P1/P2。
- 只有理论可能、无法证明输入可控或已被上下游防护阻断时不要报告。
