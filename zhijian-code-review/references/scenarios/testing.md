# 测试审查规则

## 必须考虑的覆盖

- 变更后的主成功路径、真实失败路径、边界输入和兼容路径。
- 权限、租户隔离、输入验证、事务、重试、并发和迁移等高风险不变量。
- 修复缺陷时应有能在修复前失败、修复后通过的回归测试。
- 公共契约变化应覆盖旧调用方、默认值、序列化和升级顺序。

## 测试质量

- 断言可观察行为和契约，不要只断言 mock 被调用或实现细节。
- 测试必须真正进入目标分支；错误的 fixture、提前返回和宽泛断言会产生假通过。
- 异步测试必须 await 工作完成，捕获后台异常并正确使用虚拟时间。
- 并发测试避免仅靠 sleep；使用同步点、最终一致断言或 race 检测工具。
- 隔离时间、随机、网络、文件、数据库和全局状态，确保可重复且不会污染其他测试。

## 缺失测试的报告标准

只有同时满足以下条件才报告缺失测试：

1. 本次变更新增或改变了可观察行为。
2. 存在具体、可信的失败模式。
3. 现有测试未覆盖该路径。
4. 增加测试能有效防止回归，而不是为了覆盖率数字。

不要把每个改动都要求新增测试；纯文档、机械重命名或已被更高层测试充分覆盖时可不报。
